# Traverse

Exact directed shortest paths on a road-like graph, built for the end-to-end clock: parse, preprocess, answer, write. Every phase uses all workers (`SD_THREADS`, default up to twelve).

1. **Parse.** `graph.txt` is mmapped and cut at line boundaries per worker. Each 64-byte block yields a separator bitmask (SSE2); every number is decoded from the 8 bytes ending at its separator. Edges go to 6-byte bin entries keyed by the tail's bucket of ids; weights of 65535 or more keep a marker and live in a side table.
2. **Raw graph.** Each bucket is turned into rows in cache: four 32-bit slots per vertex (packed `head << wbits | weight`, empty slots all ones), or, for a vertex with more than four edges, a pointer to its edges in a spill area, so reading a row is one cache miss instead of an offset plus an edge miss. Oversized weights sit in a sorted escape table. All workers' bins share one pool laid out by group of buckets; each group is unmapped (one call) as soon as its rows exist, so the bins shrink while the graph grows. Out-degree <= 2 vertices that are not query endpoints are marked bypassable.
3. **Contraction and ordering, fused.** Workers grow breadth-first regions from unclaimed survivors of their id slices. Expanding a vertex follows each out-edge through bypassable vertices (one way on, never back) to the first survivor, so degree-2 contraction, locality ordering and edge gathering are one pass. Walks of a batch advance one hop per round, and the rows of the next two batches are prefetched, so their misses overlap. Claims use plain stores: a vertex claimed twice leaves a copy with no in-edges, because every head resolves through one map entry.
4. **Renaming and reverse graph.** The new ids are cut into equal slices, one per worker, independent of region sizes (BFS regions race and can differ several-fold). A worker writes the id map for its slice, then renames the slice's gathered edges to final ids (prefetching the map 24 edges ahead) and, in the same pass, counts the in-edges of its slice; an edge into another slice is mailed to that slice's worker. One more pass places every in-edge, filling rows from their ends, so the reverse graph needs no bins and no atomics. Buffers are recycled instead of faulted in afresh: the raw rows' pages become the id map and the forward graph, and the regions' order and edge pages are moved (`mremap`) under the reverse graph's offsets and edges.
5. **Queries** run on independent workers in order of source id: an exact 256-vertex forward probe, then bidirectional Dijkstra balancing settled counts and stopping when the two queue fronts sum to the best meeting. The queue is a ring of width-128 buckets (heap for far jumps) with constant key/vertex fields, drained FIFO with lookahead prefetch. Labels are 16-bit and saturate at 65535, in 128-entry pages materialized on first write; a search that settles only below the limit is exact, and any query whose answer reaches the limit (or has no path) is recomputed with 64-bit labels. The 11-bit weight field common at this scale gets a specialized loop. Relaxations are branch-free. (Query engine from Codex PR #20.)

Exactness covers zero weights, parallel and duplicate edges, self-loops, isolated and unreachable vertices, and 64-bit sums. No third-party runtime dependencies.
